# State

**Об'єкт поводиться по-різному залежно від свого стану. Кожен стан — окремий клас,
і стан сам вирішує, куди перейти далі.**

Приклад: кнопка "Відправити" для замовлення. Неоплачене — не можна. Оплачене — можна. Вже відправлене — нічого не робить.

---

## Проблема

Без патерну в **кожному** методі той самий switch:

```java
void ship() {
    switch (status) {
        case PAID -> status = SHIPPED;
        case NEW  -> throw new IllegalStateException("Pay first");
        ...
    }
}
// і так само в pay(), cancel(), deliver()
```

Новий стан → правиш усі методи.

---

## Рішення

```
              pay()            ship()             deliver()
   NEW ──────────▶ PAID ──────────▶ SHIPPED ──────────▶ DELIVERED
    │                │
    │ cancel()       │ cancel() + повернення грошей
    ▼                ▼
          CANCELLED
```

- **Order** (context) — тримає поточний стан і просто передає йому виклик: `state.ship(this)`.
- **OrderState** — базовий клас, усі дії за замовчуванням заборонені.
- **NewState, PaidState…** — кожен дозволяє лише свої дії і сам перемикає Order далі:
  `order.changeState(new ShippedState())`.

---

## State vs Strategy

Код виглядає однаково. Різниця одна — **хто перемикає**:

| | Strategy | State |
|---|---|---|
| Хто міняє | клієнт ззовні | сам стан зсередини |
| Знають одне про одного | ні | так, стан знає наступний |

---

## Запам'ятати

1. Сигнал: однаковий `switch (status)` у кількох методах.
2. Один стан = один клас. Context лише делегує.
3. Переходи робить сам стан.
4. Від Strategy відрізняється тим, хто перемикає.
