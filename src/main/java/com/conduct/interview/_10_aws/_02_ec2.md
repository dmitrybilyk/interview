# EC2 — Elastic Compute Cloud

## What it is
Virtual machines (instances) in AWS. You choose OS, CPU, memory, network, storage. Full control.

## Instance types (family naming)
| Family | Optimized for | Examples |
|---|---|---|
| `t3`, `t4g` | Burstable general-purpose (small apps, dev) | t3.micro, t3.small |
| `m6i`, `m7g` | Balanced CPU/memory | m6i.large |
| `c6i`, `c7g` | Compute-intensive | c6i.xlarge |
| `r6i` | Memory-intensive (large heap JVM apps, caches) | r6i.2xlarge |
| `g5` | GPU (ML inference) | |

`g` suffix = Graviton (ARM, cheaper). `i` = Intel. `a` = AMD.

## Key concepts
- **AMI** (Amazon Machine Image) — OS template + pre-installed software. Basis of every instance.
- **EBS** (Elastic Block Store) — network-attached block volume. Persists after instance stop. Root volume.
- **Security Group** — stateful virtual firewall at instance level. Inbound + outbound rules by port/protocol/source.
- **Key pair** — SSH access. AWS stores public key, you keep private key.
- **Elastic IP** — static public IP that survives instance stop/start.
- **User Data** — bash script that runs once on first boot (install Java, pull config, etc.).

## Auto Scaling
- **Launch Template** — defines instance config (AMI, type, SG, role, user data).
- **Auto Scaling Group (ASG)** — maintains desired number of instances. Scale in/out on CloudWatch alarms.
- Min / Desired / Max capacity. Replaces unhealthy instances automatically.

## Load Balancers
| Type | Use case |
|---|---|
| **ALB** (Application) | HTTP/HTTPS, path-based routing, host-based routing. Use with Java web apps. |
| **NLB** (Network) | TCP/UDP, ultra-low latency, static IP. |
| **CLB** | Legacy, avoid. |

ALB → Target Group (set of EC2s or IPs) → health checks → route requests.

## Pricing types
| Type | When to use |
|---|---|
| On-demand | Default, no commitment |
| Reserved (1 or 3 yr) | Stable workloads, big savings |
| Spot | Fault-tolerant, batch, stateless — can be interrupted with 2 min notice |
| Dedicated Host | Compliance requiring physical isolation |

## Interview points
- EC2 is IaaS — you manage OS, patching, scaling.
- For Java: size instance for heap (`-Xmx`) + OS overhead. r6i for large heaps.
- ASG + ALB = standard HA pattern: spread across AZs, replace failed instances automatically.
- Spot interruption: Lambda or SQS workers on Spot are ideal (stateless, short-lived).
