# S3 — Simple Storage Service

## What it is
Object storage — store any file as an object with a key inside a bucket.
Not a file system (no directory rename), not block storage (can't mount like a disk).
Virtually unlimited capacity. 99.999999999% (11 nines) durability.

## Core concepts
- **Bucket** — global namespace container. Name must be globally unique across all AWS accounts.
- **Object** — file + metadata. Key = full path (`images/user/avatar.png`). Max size 5 TB.
- **Region** — bucket lives in one region. Data doesn't leave it unless you configure replication.

## Storage classes (cost vs retrieval speed)
| Class | Use case | Retrieval |
|---|---|---|
| **Standard** | Frequently accessed | Instant |
| **Standard-IA** | Infrequent access, still fast | Instant, retrieval fee |
| **Intelligent-Tiering** | Unknown pattern, auto-moves between tiers | Instant |
| **Glacier Instant** | Archival, accessed once/quarter | Instant |
| **Glacier Flexible** | Archival | Minutes to hours |
| **Glacier Deep Archive** | Rarely ever accessed | Hours |

## Key features
- **Versioning** — keeps all versions of an object. Protects against accidental delete/overwrite.
- **Lifecycle rules** — auto-transition objects to cheaper class after N days, or expire/delete.
- **Replication** — CRR (cross-region) or SRR (same-region). Requires versioning enabled.
- **Static website hosting** — serve HTML/JS/CSS directly from a bucket.
- **Event notifications** → trigger Lambda, SQS, or SNS on `s3:ObjectCreated`, `s3:ObjectRemoved`, etc.

## Access control
- **Bucket policy** (resource-based JSON) — control access from other accounts, public access.
- **ACL** — legacy, prefer bucket policies.
- **Block Public Access** — account/bucket-level setting, overrides any public grant. Always enable for private data.

## Presigned URLs
Temporary URL granting access to one object without exposing credentials.
```java
S3Presigner presigner = S3Presigner.create();
PresignedGetObjectRequest presigned = presigner.presignGetObject(r -> r
    .signatureDuration(Duration.ofMinutes(15))
    .getObjectRequest(req -> req.bucket("my-bucket").key("report.pdf")));
String url = presigned.url().toString();  // share this URL
```
Use case: let browser upload/download directly to S3, bypassing your server.

## Multipart upload
For files > 100 MB. Split into parts (5 MB–5 GB each), upload in parallel, complete.
SDK `TransferManager` handles this automatically.

## Java SDK
```java
S3Client s3 = S3Client.builder().region(Region.EU_WEST_1).build();

// Upload
s3.putObject(r -> r.bucket("my-bucket").key("data.json"),
             RequestBody.fromString("{\"a\":1}"));

// Download
ResponseBytes<GetObjectResponse> obj =
    s3.getObjectAsBytes(r -> r.bucket("my-bucket").key("data.json"));
String content = obj.asUtf8String();

// Delete
s3.deleteObject(r -> r.bucket("my-bucket").key("data.json"));
```

## Interview points
- S3 is eventually consistent for overwrites/deletes (was; since 2020 it's **strongly consistent** for all operations).
- Flat structure — "folders" are just key prefixes with `/`. No rename = copy + delete.
- Max PUT size: 5 GB in single request. Use multipart for anything > 100 MB.
- Transfer Acceleration — routes uploads through CloudFront edge for faster global uploads.
- S3 Select — run SQL queries on CSV/JSON stored in S3 without downloading the whole file.
