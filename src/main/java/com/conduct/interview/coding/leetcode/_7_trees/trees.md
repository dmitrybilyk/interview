# Дерева — коротка теорія

## 1. Що таке дерево

Дерево — це вузли, з'єднані так, що **немає циклів**, і до кожного вузла веде **рівно один шлях** від кореня.
По суті, це граф без циклів з одним "початком".

```
               1          ← root (корінь): вузол без батька         depth 0
             /   \
            2     3       ← 2 і 3 — діти (children) вузла 1          depth 1
           / \     \        2 і 3 — брати (siblings)
          4   5     6     ← 4, 5, 6 — листки (leaves): без дітей     depth 2
```

| Термін | Значення | На прикладі |
|---|---|---|
| **root** | верхній вузол, без батька | `1` |
| **parent / child** | батько / дитина | `2` — батько для `4` і `5` |
| **leaf** | вузол без дітей | `4`, `5`, `6` |
| **subtree** | вузол + усі його нащадки — теж дерево | `2 → 4, 5` |
| **depth** вузла | скільки ребер від кореня **до** вузла | depth(`5`) = 2 |
| **height** дерева | кількість рівнів (на LeetCode — вузлів на найдовшому шляху) | 3 |

> Майже всі задачі на дерева розв'язуються рекурсією, бо **кожне піддерево — теж дерево**.
> Розв'язуєш задачу для `root.left` і `root.right`, а потім поєднуєш результати.

## 2. Види дерев

### За кількістю дітей
- **Binary tree** — у кожного вузла ≤ 2 дітей (`left`, `right`). Основа майже всіх задач LeetCode.
- **N-ary tree** — дітей скільки завгодно (`List<Node> children`). Наприклад, файлова система або DOM.

### За формою бінарного дерева

```
  Full                Complete              Perfect             Degenerate
  (0 або 2 дітей)     (заповнене зліва)     (усі рівні повні)   (по суті список)

      1                   1                     1                1
     / \                 / \                  /   \               \
    2   3               2   3                2     3               2
       / \             / \                  / \   / \               \
      4   5           4   5                4   5 6   7               3
                                                                      \
                                                                       4
```

- **Full** — кожен вузол має 0 або 2 дітей.
- **Complete** — всі рівні повні, крім останнього, і він заповнюється **зліва направо**. Саме так влаштована **heap** (її зберігають у масиві).
- **Perfect** — всі рівні повністю заповнені. Вузлів `2^h − 1`.
- **Balanced** — висоти лівого і правого піддерева кожного вузла відрізняються не більше ніж на 1. Висота ≈ `log n`.
- **Degenerate** — кожен вузол має одну дитину. Це фактично linked list: висота `n`, і всі операції стають O(n).

### За правилами розташування значень

**BST (Binary Search Tree)** — для **кожного** вузла: всі значення зліва **менші**, всі справа **більші**.

```
            8
          /   \
         3     10          ліве піддерево 8: {1, 3, 6}   — всі < 8
        / \      \         праве піддерево 8: {10, 14}   — всі > 8
       1   6      14
```

- Пошук, вставка й видалення — йдемо вліво або вправо, як у бінарному пошуку: **O(h)**.
- **Inorder-обхід BST дає відсортований список**: `1 3 6 8 10 14`. Це головний трюк у задачах на BST.
- Пастка: перевіряти тільки "ліва дитина < батька" **недостатньо**, правило діє для всього піддерева.

**Self-balancing BST** — автоматично тримає висоту ≈ `log n`, щоб BST не виродилось у список (якщо вставляти `1, 2, 3, 4…`).
- **AVL** — суворе балансування, швидший пошук.
- **Red-Black** — м'якше балансування, швидші вставки. На ньому побудовані `TreeMap` / `TreeSet` у Java і бакети `HashMap` після 8 колізій.

**Heap** — complete tree, де батько ≤ дітей (min-heap) або ≥ (max-heap). Мінімум або максимум завжди в корені. У Java це `PriorityQueue`.

**Trie (prefix tree)** — кожне ребро відповідає букві, а шлях від кореня — префіксу слова. Використовується для автодоповнення і пошуку за префіксом.

**B-tree / B+tree** — у вузлі багато ключів і багато дітей, дерево дуже низьке. Так влаштовані індекси в БД (PostgreSQL, MySQL).

## 3. Обходи (traversal)

Для дерева:
```
            1
           / \
          2   3
         / \   \
        4   5   6
```

| Обхід | Порядок | Результат | Коли використовувати |
|---|---|---|---|
| **Preorder** (DFS) | **вузол** → ліве → праве | `1 2 4 5 3 6` | копіювання і серіалізація дерева, шлях від кореня вниз |
| **Inorder** (DFS) | ліве → **вузол** → праве | `4 2 5 1 3 6` | **BST → відсортовано**, k-тий найменший |
| **Postorder** (DFS) | ліве → праве → **вузол** | `4 5 2 6 3 1` | спершу потрібні відповіді дітей: висота, діаметр, видалення |
| **Level order** (BFS) | рівень за рівнем | `[1] [2,3] [4,5,6]` | рівні, найкоротший шлях, вигляд справа |

**Як запам'ятати:** pre/in/post — це місце **вузла** відносно дітей. Ліве завжди йде перед правим.

**DFS проти BFS:**

| | DFS | BFS |
|---|---|---|
| Структура | рекурсія або **стек** | **черга** |
| Пам'ять | O(h) — висота | O(w) — найширший рівень |
| Добре для | майже всіх рекурсивних задач | задач "по рівнях" і найкоротшого шляху |

Код: `_1_traversal/dfs/` (`PreorderTraversal`, `InorderTraversal`, `PostorderTraversal`), `_1_traversal/LevelOrderTraversal.java`.

## 4. Складність

| Операція | Balanced BST | Degenerate BST | Звичайне binary tree |
|---|---|---|---|
| Пошук | O(log n) | O(n) | O(n) |
| Вставка / видалення | O(log n) | O(n) | O(n) |
| Будь-який обхід | O(n) | O(n) | O(n) |
| Пам'ять рекурсії | O(log n) | O(n) | O(h) |

## 5. Шаблон рекурсивного розв'язку

Майже кожна задача на DFS має такий вигляд:

```java
int solve(TreeNode node) {
    if (node == null) return БАЗОВЕ_ЗНАЧЕННЯ;   // 1. порожнє піддерево
    int left  = solve(node.left);               // 2. довіряємо рекурсії: відповідь для лівого
    int right = solve(node.right);              //    і для правого піддерева
    return ПОЄДНАТИ(node.val, left, right);     // 3. будуємо відповідь для поточного вузла
}
```

| Задача | Базове значення | Поєднання |
|---|---|---|
| Max Depth (LC 104) | `0` | `1 + max(left, right)` |
| Same Tree (LC 100) | обидва null → `true` | `p.val == q.val && left && right` |
| Invert Tree (LC 226) | `null` | поміняти `left` і `right` місцями |

Код: `_2_dfs_problems/`.
